# 技术适配声明 — 知微 Knowence（基于 Tencent/WeKnora 改造）

> 版本：v0.2 ｜ 日期：2026-09-29 ｜ 对应 PRD：docs/PRD/PRD.md
> v0.2 变更：§6 五项决策全部关闭（品牌名定为「知微 Knowence」，产品为按自有模板重做的独立作品）。本文只描述产品形态与技术决策，供团队评审使用。

## 1. 产品形态判断

- **产品类型与核心任务**：企业私有化 AI 工作系统 =「统一 RAG 知识库 + Agent 执行 + RBAC 权限治理 + 多渠道分发」，底座能力优先。
- **核心交互**：多轮对话（RAG 直答）+ 分阶段确认（Agent 任务模式），高风险动作白名单人工确认。
- **开发路径**：不自研底座，采用 WeKnora 为骨架做二次开发；纵向切片先打通「入库→混合检索→rerank→引用回答」核心链路。
- **当前阶段范围**：MVP 四件事——建库、带引用的混合检索问答、最小 RBAC+审计、OpenAI 兼容模型层（含可切换本地推理的抽象）。

## 2. 采用的默认方案（底子选型）

## 4. 偏离或暂缓的默认方案

- **不选 Dify/FastGPT 作底座**：两者许可证均含"不得移除 logo/未经授权不得多租户 SaaS"附加条款，与"换品牌交付企业"的产品方向冲突。重新评估条件：若放弃白标需求。
- **不选 RAGFlow 作底座**：RBAC/审计/渠道需自补，等于重写半个平台。重新评估条件：若产品收缩为纯检索引擎。
- **Prompt 模板暂维持静态文件**（`config/prompt_templates/*.yaml`）：MVP 不做 Prompt DB 化+发布流；当"沙箱验证后发布"进入第二版时改为 DB 版本化（复用底座 SkillRollout 灰度语义）。
- **按角色的知识可见性下沉到 chunk 级 → 不在 MVP**：底座权限粒度是 KB 级（`access/kb_search.go` 逐 KB 判权），chunk/document 级 ACL 需下推至所有 retriever 后端，属重型改造。MVP 用「一密级一知识库 + KB 授权」近似实现数据隔离（如财务库只授权财务角色），第二版再做行级过滤。影响：合同/人事等敏感类通过分库可满足；"同一库内部分文档按角色隐藏"暂不支持——验收口径中不含此项。

## 5. 强制底线检查

- **密钥与隐私**：API Key 一律走环境变量/Secret，不进仓库不进前端；日志不落用户文档明文（沿用底座 audit details JSONB 白名单字段策略）。通过。
- **数据与任务可恢复**：任务队列面板+Worker 池为底座自带；对话/任务状态持久化在 Postgres。计划实测重启续跑。
- **输入输出校验**：模型输出结构校验、SSE 以 done/error 收尾——底座 pipeline 已有同类机制，冒烟时验证。
- **错误与日志边界**：错误统一结构返回，不泄露堆栈；审计 default-deny（API-Key scope）。
- **测试与真实模型验收**：不用 mock 冒充真实验证；MVP 验收必须接真实 API Key 跑通样例打分（PRD §4）。
