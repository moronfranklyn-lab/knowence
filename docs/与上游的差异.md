# 与上游 WeKnora 的差异说明

> 上游：[Tencent/WeKnora](https://github.com/Tencent/WeKnora) **v0.8.2**
> commit `3e8b0bfc80b845b2d4b2ed683994748741450a97`
> 上游许可证：MIT（快照内保留完整 `LICENSE` 与 `THIRD_PARTY_NOTICES.md`）
>
> **本文件的目的：让任何人一眼看清「知微 Knowence 到底改了上游什么」。**

---

## 一、总体原则

**上游代码放在 `vendor/weknora/`，本项目的改造尽量外置。**

| 目录 | 归属 | 说明 |
| --- | --- | --- |
| `vendor/weknora/` | 上游 | 上游快照 + 少量明确标注的补丁 |
| `deploy/` `docs/` `scripts/` | 本项目 | 与原目录完全独立 |
| `shots/`（工作区外） | 本项目 | 文档截图生成脚本 |
| `docker-compose.yml` `.env.example` | 本项目 | 部署编排 |

**为什么不一上来就 fork 改上游**：WeKnora 处于快速迭代期（周更，migration 编号已过百），
不锁版本的话，上游一次 breaking migration 就能让本地数据库和定制代码同时报废。
锁定后升级变成**显式决策**——先看 upstream diff，评估影响，再决定跟不跟。

### 2.3 上游文件的**零改动承诺**

以下目录**完全未动**，可安全跟随上游升级：

```
vendor/weknora/internal/        # Go 后端全部
vendor/weknora/migrations/      # 数据库迁移
vendor/weknora/mcp-server/      # MCP 服务
vendor/weknora/docreader/       # 文档解析
vendor/weknora/cli/             # 命令行工具
```

> **这一点很重要**：意味着上游的 bug 修复与安全补丁可以**直接同步**，
> 不需要处理冲突——冲突面只在 `frontend/src/` 的 31 个文件里。

## 四、升级上游的流程

```bash
# 1. 下载新版本 tarball，解包到临时目录
# 2. 先看差异，评估影响
diff -rq vendor/weknora/ /tmp/weknora-new/ | grep -v "frontend/src"

# 3. 若只涉及 frontend/src，冲突面可控：
#    保留我们的 5 个新增文件，重新应用 31 个文件的改动
# 4. 更新 docs/BASE_LOCK.md 里的 tag 与 commit SHA
# 5. 重新构建并跑品牌残留扫描
cd vendor/weknora/frontend && npm run build
```

**必查清单**（每次换锁）：
- [ ] `migrations/` 有无新增（影响数据库）
- [ ] `.env.example` 有无新增变量
- [ ] `docker-compose` profile 有无变化
- [ ] 前端是否有 breaking 的依赖升级
