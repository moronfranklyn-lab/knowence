它能做什么

五件事，一件都不含糊

底座是 Tencent/WeKnora（MIT）， 本项目在其上完成了本地化部署、双节点拆分与品牌改造。 哪些是我们做的、哪些是上游的，这份文档写得很清楚。

  • 统一知识库Word、PDF、Excel、Markdown 入库，分块可编辑、可比对、可回滚。文档改了能看出改了哪儿。
  • 有据可查的回答向量与关键词两路并发召回，重排后回填引用。知识库没覆盖的问题会明确说查不到，不猜。
  • Agent 执行ReAct 循环加工具调用。删除、改配置这类动作挂起等你确认；不可逆的操作默认拒绝。
  • 权限治理四级角色（owner / admin / contributor / viewer）、业务域知识库隔离、62 类事件审计日志，操作全程留痕。
  • 模型可换对话、向量、重排三类模型独立配置，云端和本地走同一套接口——换模型只改一行配置。

部署实录

踩过的 11 个坑，一个都没瞒着

这些不是「注意事项」，是真出过故障、翻了日志、定位到根因的问题。 每条都记了当时是怎么找到的——排查思路比结论有用。

  1. 官方镜像的 SQLite 没编译 FTS5，混合检索的关键词那一路直接失败 换用 ParadeDB 之后才有真正的向量 + 关键词双路召回
  2. 平台的 SSRF 防护会拦住内网模型地址 这是安全设计不是缺陷——允许随便填地址，就能被用来探测内网服务
  3. 从宿主机回灌数据会破坏文件属主，应用变成「能读不能写」 表症是 token 一直提示已吊销，看着像认证问题，其实是文件权限
  4. 模型名会退役，硬编码的名字某天就调不通了 所以模型名必须做成配置项
  5. 同一个模型文件，两个下载源速度差 55 倍 私有化部署常在内网，选源往往才是能不能按时交付的关键
  6. 向量模型一旦入库就不能换 不同模型的向量空间不兼容，这是数据层面的不可逆约束，必须早期定死
  7. Docker 共享挂载让推理慢了 9.4 倍 llama.cpp 用 mmap 读权重，跨层挂载让它退化成逐次读盘。模型必须放原生卷
  8. Windows 自带的 OpenSSH 装不全，而且失败时完全静默 不写事件日志、不给错误码，最后放弃系统 SSH 改用 HTTP 通道
  9. PowerShell 读 UTF-8 无 BOM 的脚本会按 GBK 解码 中文把后面的花括号吃掉了，报出毫不相干的语法错误
  10. 问答路径漏传了重排模型 ID，重排被静默跳过 配置写进去了，不等于所有入口都生效
  11. 重排的默认阈值和这个模型的分数尺度不匹配，把正确答案滤掉了 它输出的是原始 logits 不是 0~1 分数。改一个数字，生成指标涨了 18%
开始使用

三步跑起来

需要 Docker。本地模型走国内镜像源下载，约 2.2GB，脚本会直接放进 Docker 原生卷—— 放到宿主机目录再挂进去会慢 9.4 倍（见坑 7）。

  1. 取代码，填三个密钥 数据库密码、JWT 密钥、加密密钥。没填会直接报错拦下来，不会带着默认值跑起来。 
    git clone https://github.com/moronfranklyn-lab/knowence.git
cd knowence && cp .env.example .env
# 编辑 .env，改掉这三个：
#   DB_PASSWORD / JWT_SECRET / SYSTEM_AES_KEY
  2. 下载本地模型 向量模型与重排模型，自动放进命名卷。 
    ./scripts/download-models.sh
  3. 启动 首次启动要等数据库迁移和模型加载，重排模型大约 45 秒。 
    docker compose up -d
# 打开 http://localhost:8081
只想先看看
不跑本地模型也可以

把 docker-compose.yml 里的 embed 和 rerank 两个服务注释掉， 在平台设置里配云端 API 即可。平台功能不受影响，只是数据会离开内网。

环境要求
  • Docker 与 Docker Compose
  • 想跑本地模型：NVIDIA 显卡 8GB 显存起
  • 纯云端模式：4 核 8GB 内存的普通服务器即可
  • 磁盘：镜像与模型合计约 12GB
