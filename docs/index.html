数据不出内网

文档解析、向量化、检索、生成，整条链路都跑在你自己的机器上。 接入层、编排层、存储层都在内网，没有一条请求发往外部服务。

只想先用云端跑起来也行。模型层是可插拔的，换掉接入地址即可，平台功能不受影响。

有据可查

向量与关键词两路并发召回，重排之后把原文出处回填到每条结论上。知识库没覆盖的问题，它说查不到。

模型可插拔

对话、向量、重排三类模型独立配置，走同一套接口。换模型改一行配置，业务代码不用动。

它做什么

底座是 Tencent/WeKnora（MIT）。 哪些能力来自上游、哪些是本项目完成的，这份对照写得很清楚。

  • 统一知识库Word、PDF、Excel、Markdown 入库。分块可编辑、可比对、可回滚。
  • 有据可查的回答向量与关键词两路并发召回，重排后回填引用。知识库没覆盖的，它说查不到。
  • Agent 执行ReAct 循环加工具调用。删除、改配置这类动作挂起等你确认，不可逆的默认拒绝。
  • 权限治理四级角色、业务域知识库隔离、62 类事件审计日志。操作全程留痕。
  • 模型可换对话、向量、重排三类独立配置。云端与本地同一套接口，换模型只改一行。
  • 知识图谱实体与关系抽取，图谱检索可与向量检索并行。适合制度、组织、产品结构类问题。

知微是一个 Harness

模型本身不是这个产品。你用自己的模型，知微提供它们外面那层编排、检索、权限与审计。 换成别家的模型，这一层不用重写。

部署时踩过的 11 个坑

这些不是注意事项，是真出过故障、翻了日志、定位到根因的问题。每条都记了当时是怎么找到的。

  1. 官方镜像的 SQLite 没编译 FTS5，混合检索的关键词那一路直接失败 换用 ParadeDB 之后才有真正的向量与关键词双路召回
  2. 平台的 SSRF 防护会拦住内网模型地址 这是安全设计。允许随便填地址，就能被用来探测内网服务
  3. 从宿主机回灌数据会破坏文件属主，应用变成能读不能写 表症是 token 一直提示已吊销，看着像认证问题，其实是文件权限
  4. 模型名会退役，硬编码的名字某天就调不通了 所以模型名必须做成配置项
  5. 同一个模型文件，两个下载源速度差 55 倍 私有化部署常在内网，选源往往才是能不能按时交付的关键
  6. 向量模型一旦入库就不能换 不同模型的向量空间不兼容。这是数据层面的不可逆约束，必须早期定死
  7. Docker 共享挂载让推理慢了 9.4 倍 llama.cpp 用 mmap 读权重，跨层挂载让它退化成逐次读盘。模型必须放原生卷
  8. Windows 自带的 OpenSSH 装不全，而且失败时完全静默 不写事件日志、不给错误码。最后放弃系统 SSH 改用 HTTP 通道
  9. PowerShell 读 UTF-8 无 BOM 的脚本会按 GBK 解码 中文把后面的花括号吃掉了，报出毫不相干的语法错误
  10. 问答路径漏传了重排模型 ID，重排被静默跳过 配置写进去了，不等于所有入口都生效
  11. 重排的默认阈值和这个模型的分数尺度不匹配，把正确答案滤掉了 它输出的是原始 logits 不是 0 到 1 的分数。改一个数字，生成指标涨了 18%

三步跑起来

需要 Docker。本地模型走国内镜像源下载，约 2.2GB。

git clone https://github.com/moronfranklyn-lab/knowence.git
cd knowence
  1. 取代码，填三个密钥 数据库密码、JWT 密钥、加密密钥。没填会直接报错拦下来。 
    cp .env.example .env
  2. 下载本地模型 脚本会把模型直接放进 Docker 原生卷。放到宿主机目录再挂进去会慢 9 倍。 
    ./scripts/download-models.sh
  3. 启动 首次启动要等数据库迁移和模型加载，重排模型大约 45 秒。 
    docker compose up -d
# 打开 http://localhost:8081
